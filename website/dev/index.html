voxi developer docs.

voxi is a small, spec-driven Go codebase: configuration and model behavior live in version-controlled YAML, not scattered constants, and the accuracy work behind its ASR defaults is backed by real recorded-speech fixtures rather than guesswork. This page covers the parts of voxi that matter to contributors, not to everyday dictation — for that, see the main voxi page.

Spec-Driven Architecture

Spec files are the single source of truth — application code must not duplicate or shadow spec values. Every YAML file is embedded directly into the binary and validated against a companion JSON Schema. 

spec/
├── actions.yaml  # voxi monitor hotkeys & display labels
├── models.yaml   # ASR model registry & hallucination filters
├── monitor.yaml  # redraw rate & live mic-level ballistics
└── schemas
    ├── actions.schema.json
    ├── models.schema.json
    └── monitor.schema.json

spec/models.yaml names every ASR model voxi can drive and its per-model hallucination stop-words. spec/actions.yaml is the single source for voxi monitor's hotkeys — box titles and footer badges resolve their key letters from it, so they can never drift out of sync with the actual dispatcher. spec/monitor.yaml tunes the live mic-loudness meter (paint FPS, capture rate, attack/decay ballistics) without touching Go code. Run make validate-spec to check every spec file against its JSON Schema before committing.

Contributing & Workflow

voxi is a solo/hobby project on a single default branch (main), with no PR-triage web workflow — proposals, bugs, and architectural changes are tracked as Markdown files under issues/ in the repository itself.

Area Convention
Commits Conventional Commits (feat, fix, docs, refactor, test, chore)
Issues & proposals Markdown files under issues/ (e.g. issues/NNN-topic-name.md), submitted via merge requests
Go style Standard library first; external deps need explicit rationale. Allowed: spf13/cobra, gopkg.in/yaml.v3
Errors & state No panic() outside startup; wrap errors with fmt.Errorf("context: %w", err); no package-level mutable state
Tests Standard library testing, table-driven, deterministic and hermetic 
$ make help                  # Show available make targets
$ make test                  # go vet + go test across all packages
$ make validate-spec         # Validate spec/*.yaml against embedded JSON schemas
$ make check                 # Full test suite + spec validations
$ make install                # Install voxi (binary, deps, services, man page) to ~/go/bin
$ make man                   # Generate roff man page to voxi.1
$ make website-manual        # Regenerate website/man/ from the live Cobra tree

Dev Samples & Accuracy Canaries

Accuracy work on voxi's ASR defaults is backed by real recorded speech, not just synthesized fixtures. This is a private, contributor-only capability — it plays no part in everyday dictation. 

$ voxi feedback sample record <name>   # Record one utterance + corrected transcript
$ voxi feedback sample list             # List recorded dev samples
$ voxi feedback sample play <name>      # Replay a recorded sample
$ voxi feedback sample promote <name>   # Promote a noise-only sample into the public corpus
$ voxi config import <dir> --only samples  # Bring a sample set over from another machine

Each sample pairs a WAV recording with a manually corrected ground-truth transcript, stored privately under ~/.config/voxi/samples/ — never swept into any sync or backup tooling, since it holds real recorded speech. A sample confirmed to contain no real speech (keyboard clacks, mouse or ambient noise) can be deliberately promoted into testdata/noise-samples/, the repository's public, git-tracked corpus used for noise-vs-speech classification fixtures.
