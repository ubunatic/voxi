VOXI(1) General Commands Manual VOXI(1)

Name

voxi — standalone Linux voice input, continuous eager sentence streaming, and desktop typing engine

Synopsis

voxi command [subcommand] [flags]
voxi mode [batch|streaming|eager]
voxi record {toggle|start|stop|status}
voxi eager [--type] [--history] [--daemon] [--model name] [flags...]
voxi monitor [-w] [-i seconds] [-s sections]
voxi bench [--models list] [--backends cpu,gpu] [--record] [--file wav] [--json path]
voxi history {list|clear|copy ID|retype ID}
voxi config {get|set} type-delay-ms [MS]
voxi daemon modifier-service [--state-file path] [--interval dur]

Description

voxi is a voice dictation engine for Linux/Wayland built around three separable pieces: a continuous eager transcription loop, a kernel-level modifier key gating daemon, and direct synthetic keystroke injection. It runs entirely local — audio never leaves the machine and transcription is done by an on-device Whisper model.

The primary mode, voxi eager, keeps a circular pre-roll buffer so it never clips the start of an utterance, segments speech into phrases on natural conversational pauses, and transcribes each phrase as soon as it finishes — rather than waiting for the whole recording to end. Finished phrases are typed into the focused window through dotool(1), with a clipboard fallback via wl-copy(1) when direct injection isn't available.

Commands

mode [batch|streaming|eager]
Show the active voice-input mode, or switch to one of the three transcription strategies. With no argument, prints the current mode.
record {toggle|start|stop|status}
Control an active dictation recording session out-of-band, e.g. from a keybinding or the GNOME extension's top-bar toggle.
eager [flags]
Run continuous eager sentence streaming dictation. See EAGER OPTIONS below.
monitor [-w] [-i seconds] [-s sections]
Print (or, with -w/--watch, continuously refresh) a btop-style report on transcription latency, audio levels, CPU/GPU load, and the daemons voxi manages. Aliases: top, resources, stats.
bench [flags]
Benchmark transcription speed — real-time factor and speedup — for every model in spec/models.yaml on both the cpu and gpu backends. By default it transcribes a fixed, deterministic reference clip (whisper.cpp's public-domain JFK sample), fetched on demand into the user's cache directory and checksum-verified, so a run is repeatable and needs no microphone. --record benches a freshly recorded live clip instead (length via --duration), --file benches a local 16kHz mono WAV. Narrow the matrix with --models and --backends (comma lists), set --threads for the CPU runs, and dump the full report with --json path.
history {list|clear|copy ID|retype ID}
Inspect and reuse recent dictation transcripts. Local-only, treat as sensitive. copy puts an entry's text on the clipboard; retype re-injects it into the focused window.
config {get|set} type-delay-ms [MS]
Read or change the type_delay_ms field in voxtype's config.toml, preserving comments and other settings. Requires a daemon restart to take effect.
daemon modifier-service [flags]
Run the standalone evdev modifier-key monitoring service directly (normally managed as voxi-modifierd, a separate system daemon — see MODIFIER GATING below).

Eager options

--threshold N
Audio RMS energy threshold to trigger speech detection. Default 150.
--silence ms
Silence duration to finalize an utterance chunk. Default 800.
--pre-roll ms
Pre-speech circular buffer duration, preserving starting phonemes clipped by detection latency. Default 500.
--min-speech ms
Minimum speech duration to accept as an utterance rather than discard as noise. Default 200.
--max-window ms
Maximum window length before a phrase chunk is forced even without a pause. Default 8000.
--type
Type transcribed sentences directly into the focused window via dotool(1).
--history
Record transcribed utterances into local dictation history.
--daemon
Run as a background systemd service listening for record toggle control, instead of an interactive foreground session.
--model name
Whisper model to use. Default small.en, falling back to base.en.

Modifier gating

voxi-modifierd reads physical modifier key state straight from the kernel via evdev's EVIOCGKEY, independent of anything the compositor or window manager reports. It exists to solve one problem safely: dictation must be able to type while a hotkey like Super is held down — e.g. to buffer output during a push-to-talk gesture — without ever logging or reacting to any key that isn't a modifier.

The daemon polls raw modifier state at a fixed interval (default 10ms) and publishes it to a world-readable state file (default /run/voxi/modifiers), which voxi eager reads to decide when to hold typed output back versus flush it. Because it only ever inspects modifier bits, it cannot see, and never records, the content of anything else typed on the keyboard.

Model registry

Every model voxi can drive through voxtype is declared in spec/models.yaml — the single source of truth, schema-checked, with no model constants duplicated in Go. Each entry carries its own list of hallucination stop-word patterns: the phrases Whisper reliably invents on silence or low-confidence audio (“thanks for watching”, “please subscribe”, trailing subtitle credits). Those matches are filtered out before anything is typed. Keeping the list per model rather than one global hardcoded set means a model that develops its own leakage gets its own patterns, without loosening the filter for the others.

A model may also declare requires_gpu when it is measurably sub-realtime on CPU. large-v3-turbo does: RTF 2.54, a 0.39x speedup on the reference machine, i.e. it falls behind live speech and accumulates latency in eager mode. Rather than hard-failing on a GPU-less machine, the same entry names a cpu_fallback (small.en, also the current default), and voxi substitutes it automatically with a printed notice — a stated substitution instead of a silent guess or a dead command. Run voxi bench to measure your own hardware; the published baseline lives in docs/BenchBaseline.md.

Companion pieces

Key components live in Go packages under internal/, plus one GNOME Shell extension:

eager
the continuous streaming loop: pre-roll buffer, pause segmentation, and phrase-level transcription scheduling.
modifiers
evdev polling and the world-readable modifier state file consumed by the typing path.
typing
synthetic keystroke injection via dotool/dotoold with XKB layout awareness, and atomic clipboard fallback via wl-copy.
monitor
the btop-style resource report: latency sparklines, audio meters, CPU/VRAM, and AMD GPU Vulkan acceleration status.
history
append-only local transcript log backing voxi history.
voxi@ubunatic.com
GNOME Shell top-bar extension: recording toggle, mode switcher, type-delay slider, and a dictation history popup.

Examples

$ voxi eager --type --history
# dictate continuously, typing and logging each finished phrase

$ voxi mode eager
# switch the active systemd-managed mode to eager streaming

$ voxi record toggle
# flip recording on/off, e.g. bound to a hotkey

$ voxi monitor --watch --sections s,t
# live speed + transcript panels only

$ voxi bench --models small.en
# time one model on both backends against the reference clip
MODEL                BACKEND         RTF    SPEEDUP DETECTED
small.en             gpu            0.18      5.44x gpu:Vulkan0
small.en             cpu            0.53      1.87x cpu

$ voxi history list --limit 5
# most recent five transcripts

$ voxi config set type-delay-ms 8
# slow down synthetic typing for a flaky target app

Installation

# user binaries (~/go/bin)
$ git clone https://codeberg.org/ubunatic/voxi
$ cd voxi
$ make install
$ make install-user-services

# optional: system modifier-gating daemon
$ make install-modifierd
